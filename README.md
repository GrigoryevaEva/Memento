# Memento — Forgetting Curve Ebbinghaus

Клиентское приложение для запоминания по кривой забывания Эббингауза. Пользователь проходит аутентификацию, создаёт разделы и карточки, а затем повторяет карточки по расписанию. Приложение получает и изменяет данные через HTTP API бэкенда; сессия передаётся браузером в cookie.

## Конфигурация

### HTTP API

| Параметр | Назначение | Обязательный | Значение по умолчанию | Пример |
|----------|------------|--------------|-----------------------|--------|
| `VITE_API_BASE_URL` | Базовый URL HTTP API | Да | Не задано | `http://<backend-host>` |
| `VITE_STATIC_BASE_URL` | Базовый URL для статических файлов сборки | Нет | `/` | `https://cdn.example.com/memento/` |

Переменные подставляются Vite при запуске или сборке. `VITE_STATIC_BASE_URL` может быть абсолютным путём или полным URL и влияет на пути к ассетам. API должен разрешать запросы с cookie: клиент отправляет их с `credentials: 'include'`.

## Локальная разработка

Рабочая директория команд: корень репозитория.

### Подготовка

```bash
npm ci
```

### Запуск приложения

```bash
VITE_API_BASE_URL=http://<backend-host> npm run dev
```

### Проверки

```bash
npm run lint
VITE_API_BASE_URL=http://<backend-host> VITE_STATIC_BASE_URL=https://cdn.example.com/memento/ npm run build
```

Тестовый скрипт в `package.json` не найден.

### Полезные локальные действия

```bash
npm run lint:fix
VITE_API_BASE_URL=http://<backend-host> npm run preview
```

`npm run preview` запускает предварительный просмотр уже собранной версии, поэтому сначала выполните `npm run build`.

## Краткая документация

### Entrypoint

- `src/main.ts`: создаёт Vue-приложение, подключает Vue Router и Pinia, затем монтирует его в `#app`.

### Интерфейсы и контракты

- HTTP API: `POST /api/auth/login`, `/api/auth/logout`, `/api/auth/register`, `/api/auth/demo`; `GET /api/auth/me`.
- Разделы: `GET` и `POST /api/section`, `PATCH` и `DELETE /api/section/:id`.
- Карточки: `POST /api/card`, `PATCH` и `DELETE /api/card/:id`.
- Маршруты UI: `/`, `/login`, `/sections/:id/cards`, `/repetition`, `/plan`.

### Поток обработки

1. При загрузке `App.vue` проверяет текущую сессию через `/api/auth/me`.
2. После успешной проверки приложение получает разделы и карточки через `/api/section`.
3. Pinia stores хранят данные и вызывают API при создании, изменении, удалении и повторении карточек.
4. Vue Router показывает доступные страницы только аутентифицированному пользователю.

### Кодовая структура

| Путь | Назначение |
|------|------------|
| `src/main.ts` | Инициализация приложения |
| `src/app/` | Корневой компонент, роутинг и Pinia |
| `src/pages/` | Страницы аутентификации, разделов, карточек, плана и повторения |
| `src/stores/` | Состояние пользователя, разделов, карточек и запросов |
| `src/api/` | HTTP-клиент и контракты API |
| `src/shared/` | Общие UI-компоненты, стили, иконки и переводы |

### Ограничения и особенности

- URL API обязателен: без `VITE_API_BASE_URL` запросы не смогут сформировать корректный URL.
- Автоматизированные тесты и CI-конфигурация в репозитории не найдены.
- Для dev-сервера в `vite.config.ts` разрешён хост `frontend.dev.test`.
